# Development

This page tells how to build and test CineCam, the console commands, the local control, and the checks for a game update. Back to the [README](../README.md).

## Building and tests

Targets **.NET 10**. The project references the game DLLs with the path `..\..\..\refs\game\` from `CineCam\CineCam.csproj`, so the install folder of the game (or a link to it) must exist at that place, three folders above the project folder.

| Package | Source | Tested Version |
| --- | --- | --- |
| [StarMap.API](https://github.com/StarMapLoader/StarMap) | NuGet | 0.5.2 |
| [Lib.Harmony](https://www.nuget.org/packages/Lib.Harmony) | NuGet | 2.4.2 |

```
dotnet build CineCam.slnx -maxcpucount:4 -p:DeployToMods=false
dotnet run --project CineCam.Tests --no-build -maxcpucount:4 -p:DeployToMods=false
dotnet run --project CineCam.ControlTests --no-build -maxcpucount:4 -p:DeployToMods=false
dotnet run --project CineCam.ApiTests --no-build -maxcpucount:4 -p:DeployToMods=false
```

A command-line build only compiles. It copies the mod into a game folder only with `-p:ModDeployDir=<folder>\mods\CineCam\` or `-p:DeployToMods=true` (the profile in Documents), and then fails while the game runs. A build inside Visual Studio deploys into the profile in Documents. `-p:DeployToMods=false` keeps a build compile-only in every case.

`CineCam.Tests` is a console program that runs without the game. It tests the shot file reader and writer, the timeline layout, the presets, the pose math, the event detector, the speed rules, the actions and the stage guard, the local horizon frame, the fired sequence detection, the offline frame bookkeeping and the picture collector. It exits with 0 when all tests pass. The Python tools have their own tests: `python -I scripts/test_events_to_markers.py` and `python -I scripts/test_cinecam.py`.

`CineCam.ControlTests` links the picture guard, frame statistics, still capture and capture hooks against small game stand-ins, without loading KSA or a renderer.
It tests the Harmony save prefix and finalizer on successful and failed saves, interface restore across a still warm-up and unload, quit refusal in every still phase, terminal explosion triggers and event times from older runs.
The control tests also check the FPS preference during a save and hold a PNG task open after the GPU grab ends.
The sound tests stall the WAV writer and check quit refusal until the final header has been written and the file is closed.
These tests do not verify the Vulkan capture or the hook order inside the game.

The mod has a self test that runs inside the game. It is off unless the environment variable `CINECAM_AUTOTEST` names a result folder. It plays a take of every shot type in real time and an offline take, checks the event log, the return of the camera and the game sound (the real-time take records `game-sound.wav` without a change of the settings file, and the offline take must record none), and writes `result.json` in the result folder.

## Console commands

Open the game console and run:

| Command | Action |
| --- | --- |
| `cinecam_start [take]` | Starts the named take, or the default take |
| `cinecam_stop` | Stops the running take |
| `cinecam_reload` | Checks the shot file |
| `cinecam_pause` | Pauses the running take for an edit, or resumes a paused one |
| `cinecam_mark` | Gives a mark in the running take or flight recording: the events `mark`, `mark:2` and so on |
| `cinecam_checkpoint [take]` | Saves the game as the checkpoint of the take |
| `cinecam_reset [take]` | Ends a running take, loads the checkpoint and makes the take ready |
| `cinecam_still [scale]` | Saves one picture of the current view at 2 to 8 times the window size into `CineCam\stills`. Without a scale it uses the setting `stillScale` |
| `cinecam_sun [elevation] [set]` | Moves the game time to the next time the sun at the launch site has this elevation in degrees. Add `set` for a sun that goes down |

## Local control from a terminal (developer mode)

Set `"enableLocalControl": true` in the instance's `CineCam\settings.json` and restart KSA. CineCam creates `CineCam\control` in that instance's game data folder. Run the included `scripts/cinecam.py` with Python 3.11 or later. Without options the CLI uses `CineCam\control` in the game's Documents folder. For another instance, set `CINECAM_CONTROL_DIR` to the control folder or give its path with `--control-dir`. When the folder has no running session, the CLI says which folder it checked. Preview frames go to `CineCam\previews\`; CineCam removes preview folders that are older than one hour when it takes the next preview.

The CLI prints JSON with `ok`, `code`, `message` and the current `state` when the game responds. The state has the take time and the recording time, the take that plays, the camera, and the events with their recording and take times (the first 1000 events and separations, with `eventCount` and `markerCount` for the whole number). Use `list` to find recording IDs. Times are take seconds, the time of the video. The commands below use example IDs.

```powershell
python cinecam.py list
python cinecam.py open "Flight 2026-11-10 17-00-00 abcd1234"
python cinecam.py seek 12.5
python cinecam.py play
python cinecam.py speed 0.5
python cinecam.py camera free
python cinecam.py follow 1
python cinecam.py fov 35
python cinecam.py add-key orbit
python cinecam.py preview
python cinecam.py render --from-here
python cinecam.py render-stop
python cinecam.py close
python cinecam.py reload
python cinecam.py select-take launch
python cinecam.py quit
```

`open --older-build` confirms the open of a recording of an older game build; without it such an open is refused with the code `older_game_build`, and a recording of a later build is refused with `game_version_mismatch`. The state has `recordingBuild` and `gameBuild`, and `warning` says what the open replay shows differently from the flight. `add-key` takes `fixed`, `track`, `chase`, `orbit`, `part-mount` or `path-point` and adds the shot to the selected take of the editor at the replay time. The preview command pauses playback and returns the PNG path in `previewPath`. `render` starts a render of the take of the open replay (`--from-here` starts at the replay time), `render-stop` stops it after the current picture, and the field `render` of the state has its progress and, after the end, its result. `reload` reads the shot file of the editor again, as **Reload** of the window does, and keeps the selected take when the file still has it. It is refused while a take runs, and while the editor has unsaved changes unless you add `--discard`. `select-take` selects a take of the editor by its name, in any case; an open replay then plays it. The state names the takes in `takes`, the selected one in `selectedTake`, the file in `shotFile` and unsaved changes in `unsavedChanges`.

`quit` ends the game after it closes an open replay.
An active capture, a take, a flight that records or waits to be saved, or a reset blocks this command.
A PNG write can still block quit with `capture_busy` after its capture ends.
A WAV writer that is still closing the file blocks quit with `sound_pending`.
`stop` replies after it saves the recording. A stop on a destruction frame can wait one frame for the last effects. A save error returns `file_error`, and `retry-save` can save the retained flight.
Use `--help` for the remaining commands (`status`, `record`, `stop`, `retry-save`, `pause`, `interface`).
Any program on this computer that can write to the control folder can send these commands, so leave it off unless you use it.

## Integration API

Other mods subscribe to `CineCam.Api.CineCamEvents` through reflection. See [Integration for other mods](integration.md). `CineCam.Tests/IntegrationTests.cs` covers the public API and cue actions. `CineCam.ApiTests` links the production feed and tests event order, run boundaries, and callbacks that close the replay or render. Run `python -I scripts/test_integration_example.py --scratch <test-folder>` to compile the documented example and check its state over pauses, seeks, repeated cues, a render and a close. These tests need .NET 10 and run without game assemblies.

## Maintenance on each game update

The mod patches game methods with Harmony and reads private game members by reflection, so each game update can break it. `GameReflection` resolves the takes targets at start-up, and `ReplayPatches` applies the replay patches. A missing target turns off its feature and logs a warning or an error. On each game update, check every item below in the new decompiled source, then do one test in the game: a quick camera, a take with the default shot file, an offline take, a replay of a short recording, and a sun move. Change `TestedGameVersion` in `Mod.cs`.

### Harmony patch targets of the takes (`CineCamPatches.cs`)

`CineCamPatches.Apply` applies one group per feature. A group whose target is missing, or whose `Harmony.Patch` call throws, is off with one log line that names the features it turns off, and the other groups still go in. `Mod.Unload` removes all patches that went in. `CineCamPatches.FrameBlock` and `CineCamPatches.CameraBlock` give the reason when the frame group or the camera group is off. The take, dry run, shot preview, quick camera, checkpoint, reset, pause, reload and sun move requests (keys, window buttons and console commands) are refused with that reason, the window shows it on the disabled buttons, and the self test writes it into `result.json` and ends the game with exit code 1.

- `Program.OnFrame(double currentPlayerTime, double dtPlayer)`: a prefix and a postfix. The prefix parameter names must stay the same, because the offline capture changes both values by reference. The frame order must still be `PrepareFrame`, then `OnFrameViewports`, then the render and `PostRender`. The quick camera, the takes, the checkpoints and resets, the sun move, the self test and the replay preview pictures and render run in this prefix and postfix. Without it a replay still opens and plays, because it runs in the replay patches.
- `FixedController.OnFrame(IViewport, double)`: a prefix that sets the camera and skips the stock controller of the main viewport, for a take and for a quick camera. It must still run after the vehicles have their new state and before `Camera.OnFrame` builds the matrices. Without it no take, dry run, shot preview or quick camera starts, and a reset does not start its take. The take camera of a replay does not need it, because the replay camera follows nothing and `FixedController.OnFrame` moves the camera only while it follows something.
- `FixedController.OnSwitchOn(CameraMode)`: a prefix that skips the "Fixed camera" alert during a take. Without it, the alert stays.
- `Program.OnKey`: a prefix and a postfix that read the parameters `key` (`GlfwKey`) and `action` (`GlfwKeyAction`). The guard must match the one in the game: `Program.IsLoaded`, `ImGui.GetIO().WantCaptureKeyboard`, `Program.ConsoleWindow.IsOpen`, and the part picker (`PartPicking.OnKey` takes the cancel key while `PartPicking.IsActive`; the prefix stores `IsActive`, and a key that ended the pick is skipped).
- `Universe.GetJobSimStep(double)`: a prefix that writes the hold of a reset and the speed track of a take again, because `Vehicle.UpdateControl` and `Vehicle.UpdateProbePowerWarning` can set the speed to 1x earlier in the same frame for an uncrewed vehicle, and a postfix that reads `SimStep.DeltaTime` to find a step that `Universe.LimitNextStep` cut in an offline capture. The prefix reads the parameter `dtPlayer` as `__0`. The prefix also calls `Universe.LimitNextStep(UniverseTime)` for the target of the sun move and for the apsides of an offline take with `exactApsides` (`Orbit.GetNextApoapsisTime`, `Orbit.GetNextPeriapsisTime`, `Orbit.GetOrbitType`, `Vehicle.Situation.HasAnyContact()`). `Universe.ApplyVehicleSolvers` must still clear the limit (`_stepLimitTime`) before this method, `GetJobSimStep` must still cut the step at the limit when it lies after `_lastSimStep.NextTime`, the step must still grow by at most twice the step before (`_maxStepSimSeconds`), and `Universe.ProcessAutoWarp` must still end the warp when the game time reaches `SimTimeAutoWarpEnd`. The step must still come from `GetSimulationSpeed()` read inside this method. Without the patch a take can run one frame at 1x after such a stop, the sun move ends up to one step past its target and counts 0.5 s early, and an offline take lands no picture on an apsis.
- `Program.DrawFps()` (private, static): a postfix that draws the white sync frame. It must still run when `Program.DrawUI` is false. It must still draw the frame statistics only when `GameSettings.ShowFrameStatistics()` (`GameSettings.Current.Interface.FrameStatistics`) is true, because CineCam turns that field off while it hides the interface.
- `GameSettings.Show` (the property setter, parameter `value`): a prefix that gives the frame statistics and the picture settings of the player back before the setter copies `GameSettings.Current` into the settings window (`_temporary`), which `SaveChanges` and Apply then save. Without it the picture settings of a take apply only while the interface is hidden.
- `GameSettings.Save()`: a prefix that restores the player values of pinned picture fields and suppressed frame statistics for serialization, and a finalizer that reapplies the temporary values even if the save throws. `CrewClock.Toggle` and `ToggleCollapsed` call this method directly. The patch reads `__instance` and carries an `Action` in `__state`. Picture pins and frame statistics suppression require this patch.
- `ConsoleWindow.Draw(float2, float2, float, bool)`: a prefix that skips the console while a take hides the interface, or while a replay hides it.
- `UncompressedSave.ApplyLoaded()`: a postfix with `__instance` and `__runOriginal`. It observes the applied save object after `Universe.DeserializeSave` and `Program.OnGameLoaded` finish. `SaveSystemSwap.RequestLoad` can call this method immediately or queue it for `SaveSystemSwap.OnFrame`. The reset waits up to 20 s for that exact object to apply before it starts waiting for the vehicle. Without the hook, a reset can detect a new controlled vehicle during the load call.
- `ScreenshotCapture.Request(int, string)`: a prefix that keeps stock screenshot requests out while a CineCam capture owns the slot or a native PNG task runs. The stock screenshot key and console command must still call this method.
- `ScreenshotCapture.OnPostRender()`: a prefix that finds out whether the frame has a picture, a transpiler that tracks the single `Task.Run(Action)` which calls `SaveToPng`, and a finalizer that reapplies the latest interface state after a clean grab. The PNG task can run after the native capture returns to Idle. A still, preview, offline take or render owns the slot through collection. When an operation times out or cancels, a later request waits until any saved task ends and snapshots the source folder before its grab. `Program._screenshotCapture`, `ScreenshotCapture.IsActive` and `ScreenshotCapture.Abort()` let teardown end an owned grab. `ScreenshotCapture.OnPrepareFrame`, `OnPostRender` and `Abort` must still save, force and restore `Program.DrawUI` as a capture starts and ends.
- The render of a replay uses the same `Program.OnFrame` prefix and postfix as the offline capture, so `Program.OnFrame` must still call `PrepareFrame` (where the replay commands run) before `OnFrameViewports` (where the replay sets the camera). It writes its progress into `Program.GetWindow().Title` (`GlfwWindow.Title`) and gives the old title back at the end. At the end it removes the alerts that the game made during the render from the private list `TimedAlert.All` (without that list the alerts stay), and the key postfix closes `EscMenu.Open` when Escape stopped the render.
- `SequenceList.ActivateNextSequence(Vehicle)`: a prefix and a postfix that read `GetNextSequenceNumber()`, `ActiveSequence` and `Count` before and after. The postfix parameter must stay named `vehicle`.
- `EVADoor.SpawnEva(Vehicle, IVASeat, KittenRosterEntryData, Camera)`: a prefix that stores `Program.ControlledVehicle` and a postfix that reads the parameter `vehicle` (`FlightHooks`). The method must still give the control to the new `KittenEva` at its end (`Program.ControlledVehicle = kittenEva`), because the postfix counts an EVA only then. The take and the live events of the window stay on the vehicle while the controlled vehicle is a kitten that left it. Without the patch the event `eva` never comes, and an EVA ends the take as before ("the controlled vehicle changed").
- `KittenEva.BoardVehicle(Vehicle, EVADoor)`: a postfix that reads the parameter `host` and the result `CrewSeatResult` (`Seated` counts). Without it the event `board` never comes.
- `ExplosionSystem.SpawnForDestruction(in ExplosionContext)`: a postfix that reads the parameter `context` (`Vehicle`, `Part`, `Cause` with the names of `VehicleDestructionCause`). Every destruction with an explosion must still go through it (`PartFailureEvent.Apply`, `Universe.DestroyVehicleFromEvent`), and the method must still drop a call from another thread (`Program.IsMainThread()`). Without the patch the event `explosion` never comes.

### Harmony patch targets of the replay (`ReplayPatches.cs`)

A required target that is missing turns the whole replay off. An optional target logs a warning, and the replay then runs without it.

Required:

- `Program.RefreshVehiclesInFrame()`: a postfix that samples the flight for the recorder.
- `Program.OnFrameViewports(double)`: a prefix that advances the playback.
- `Vehicle.Split(Part.Connection, Part.Connection.IConnector, double, out PoseChange, string)`: a postfix that records a split-off stage.
- `PartModelRenderer.UpdateRenderData(IViewport, int)`: a prefix that draws the recorded parts.
- `Vehicle.UpdateRenderData(IViewport, int)`: a prefix that skips the live vehicles in the replay.
- `Vehicle.UpdateExhaustLights(Camera, IViewport)` and `Vehicle.AddVolumetricExhaustInstances(Camera, VolumetricExhaustRenderer, double)`: prefixes that skip the live exhaust.
- `VolumetricExhaustRenderer.EndPlumeGrouping()`: a prefix that draws the recorded plumes.
- `Program.UpdateShaderData(double, IViewport)`: a transpiler that replaces the call of `Camera.GetPositionEgo(IPosition)` for the sun. The call must still exist.
- `VolumetricExhaustRenderer.UpdateFrameData()` and `VolumetricExhaustRenderer.EndPlumeGrouping()`: transpilers that replace the call of `Universe.GetElapsedSeconds()`. The call must still exist in both.
- `Universe.DeserializeSave(UniverseData)` and `Universe.LoadSystem(string)`: a prefix and a finalizer that close the replay when the world changes.
- `Universe.SetSimulationSpeed(double, bool)` and `Universe.SetSimulationSpeed(SimSpeed)`: prefixes that keep the sim stopped.
- `Universe.GetJobSimStep(double)`: a prefix that stops an automatic warp and keeps the speed at 0.
- `Vehicle.ProcessInput(InputAction, GlfwKeyAction, GlfwModifier)`: a prefix that skips the flight input in the replay.

Optional:

- `KittenEva.ProcessInput(InputAction, GlfwKeyAction, GlfwModifier)`: the same prefix for a kitten on EVA.
- `Universe.SeekNextVehicle(SeekDirection)` and `Universe.SeekNextCelestial(SeekDirection)`: prefixes, so the vessel and body keys do not change the controlled vehicle under the replay.
- `KittenEva.UpdateRenderData(IViewport, int)` and `Vehicle.UpdateParachuteRenderData(IViewport)`: prefixes that hide the live kittens on EVA and the parachutes.
- `Vehicle.UpdateSeatedCrewRenderData(IViewport, int)`: suppresses live seated crew. Replay crew draws from the unconditional `SuperMeshRenderSystem.ClearBuckets(IViewport)` postfix, so it remains visible without a controlled live vehicle. `KittenRenderable.UpdateRenderData` does not use its frame-index argument in this build; verify that before retaining the replay value 0.
- `VolumetricTrailRenderer.PrepareAndRenderShadowCascades`: a prefix that sets the `Celestial` parameter to null so no plume trail is drawn. The method is found by its parameter type names (`CommandBuffer`, `IViewport`, `Celestial`, `Int32`), so a change of that list turns the patch off.
- `KittenEva.UpdateRenderData(IViewport, int)`, `Vehicle.UpdateParachuteRenderData(IViewport)` and `Vehicle.UpdateSeatedCrewRenderData(IViewport, int)`: prefixes that hide the live kittens, parachutes and seated crew.
- `VolumetricTrailRenderer.PrepareAndRenderShadowCascades`: a prefix and a postfix around the preparation of the volumetric trails of the replay view. The method is found by its parameter type names (`CommandBuffer`, `IViewport`, `Celestial`, `Int32`), so a change of that list turns the patch off. With the explosion patches below in place, the prefix marks the time in which `VolumetricTrailRenderer.PrepareFrame` copies the trail segments, so the replay draws its explosion volumes without the live plume trails; without them it sets the `Celestial` parameter to null, so no plume trail and no explosion volume is drawn.
- `PlumeTrailSegmentsManager.CopySegmentsTo` and `PlumeTrailSegmentsManager.CopyShadowSegmentsTo` (each found as the only method of its name): prefixes that return 0 segments while the replay view prepares, so no live plume trail and no trail shadow is drawn. `VolumetricTrailRenderer.PrepareFrame` and `VolumetricTrailShadowCascades` must still take the trail segments only from these two methods, and the explosion volumes from `ExplosionVolumeManager.CopySegmentsTo`.
- `ExplosionVolumeSettings.CreateTimingProfile()`: a prefix that gives the replay time (`ExplosionTimingProfile(now, simulationDeltaTime)`) to every time read of the explosion volumes: `ExplosionVolumeManager.BeginFrame` (the removal of burned out volumes), `ExplosionVolumeSpawner.Spawn` (the start time and the merge), `ExplosionVolumeUploadBuilder.CopySegmentsTo` and `ExplosionVolumeLights.Submit`. They must still read the time only there, and `ExplosionVolume` must still be aged by `SpawnTime` and `GetAgeSeconds(now)`. Without this patch, or without one of the two trail patches above, the replay shows no explosion volume and no plume trail.
- `ExplosionVolumeManager.Spawn(ExplosionVolumeTemplate, Celestial, double3, double3, float, float)`: a prefix and a postfix that record each volume while a recording runs. The postfix reads the noise seed of a new volume as the last item of the private store (`ExplosionVolumeManager._store`, an `ExplosionVolumeStore` whose `Add` appends while it has room); a merge into a burning volume adds none. The patch parameters are `__instance`, `__state` and `__0` to `__5`.
- `ExplosionSystem.SpawnForDestruction(in ExplosionContext)`: a postfix (`ref ExplosionContext __0`) that records the destruction on the main thread (`Program.IsMainThread()`). It reads `Vehicle`, `Part`, `IntensityJ`, `PropellantMassKg`, `AmbientPressurePa` and `Cause`.
- `SuperMeshRenderSystem.ClearBuckets(IViewport)`: a postfix draws recorded canopies and seated/EVA crew after the main viewport mesh buckets are cleared. Check its order against `Program.RenderViewport` and the screenshot render path. Live crew and canopy draw methods remain suppressed separately.
- `ParticleSystem<ParticleUpdateData, ParticleRenderData>.WriteCommandsColorOpaque` and `WriteCommandsColorTranslucent`: prefixes that skip the particles. They are found by the parameter type names `CommandBuffer`, `IViewport` and `Int32`.
- `CloudLayerRenderData.UpdateCommonFrameData(int, int, double, double4x4)` and `CloudShadowVolume.GetPlanetToCloudRotation(CloudLayerRenderData)` (private, static): transpilers that replace the call of `Universe.GetElapsedSeconds()`, so the cloud layers and their shadows turn to the recorded moment. The turn must still be `AngularRotationSpeed` times the game time. Without the patches the replay shows the clouds and the cloud shadows of the moment at which it opened, and a cloud shadow can darken the vehicle and the ground where the live flight was in the sun.
- `OceanFFT.EvolveSpectrums` (private, found by the parameter type names `CommandBuffer`, `IViewport`, `int2` and `BarrierBatch&`) and `OceanRenderData.UpdateTangentFrameData(double3, int, doubleQuat, doubleQuat, float4x4)`: transpilers that replace the one call of `Universe.GetElapsedSeconds()` in each, so the waves show the recorded moment. Without the patches the waves stay as they were when the replay opened.
- `AuroraRenderer.FillAuroraData(ref AtmosphereData, AtmosphericBody, float3)`: replaces exactly two game-time calls and one `StormState.Get(Celestial, double)` call. `ReplayStormCache` caches each recorded body/time result and calls private `StormState.Compute(Celestial, double, double, out StormEffects)` without overwriting the live sample cache used by Space Weather. Verify the private method and measure paused/playing replay with simultaneous live storm queries.
- `CloudRenderer.RenderWithCompute(AtmosphericBody, CommandBuffer, IViewport, int, int, VkDescriptorSet, VkDescriptorSet, ByteSize, out bool)` (found by the parameter type names): a transpiler that replaces the one call of `Universe.GetLastSimStep()` with a `SimStep` whose `DeltaTime` is the recording time of the frame (`ReplayFrameStep`). The game must still advance the flow map phases and the noise scroll of `CloudLayerRenderData` only once per `Program.FrameNumber`. Without the patch the small cloud detail stands still in the replay.
- `PowerConsumer.ComputeStatus(PartTree)`: a prefix that returns the recorded status for a power consumer of a decoded tree that the replay shows. `PartTreeRenderData.ComputeOwnerDynamicState` must still colour the status light of the first consumer with `HasStatusLight` of a part from this method. Without the patch the probe cores show the status that the game computes from the decoded tree.
- `GroundClutterRenderer.UpdateShadowCullingData(Camera, Celestial, int, int)`: a transpiler that gives the sun of the recorded moment to the shadow culling of the ground clutter, through the same replacement of `Camera.GetPositionEgo(IPosition)` as in `Program.UpdateShaderData`.
- `FixedAlert.Draw(float, double)`: a prefix that skips the alert "Simulation paused" while a replay is open. It finds that alert once in the private array `FixedAlert.All` by the private field `_displayName` equal to `LStrings.AlertSimulationPaused`. Without the patch, or when the lookup finds nothing, the alert shows over the replay view; a render hides the interface, so it is never in a picture.
- `VolumetricExhaustRenderer.EndPlumeGrouping()`: a postfix that lights the recorded plumes. It needs `VolumetricExhaustInstance.LastPlumeData`, which `EndPlumeGrouping` computes. The light copies `Vehicle.UpdateExhaustLight` (the template values `Absorption.Density`, `Absorption.ScatteringBrightness`, `Emission.Brightness`, `Emission.ColorGradient.WeightedAverageColor`, the `StartupTransient` curve `EmissiveSizeCurve`, and `Program.LightSystem.CreateLightInstance` with `Light.CreatePointLight`), so check that method on an update. Without the patch the recorded plumes give no light.
- `ChannelWrapper.HandleSimSpeedPitch()`: a prefix that gives the sounds of the replay (the leaves of the channels that `ReplaySound` started, found by reference) the pitch factor of the replay rate and skips the method for them. It copies the rule of the method (`SoundReference.SimSpeedRule`: `Ignore` keeps 1; `All` and `OnlyHigher` give `min(1 + speed / 5, 3)` from speed 1 up; `All` and `OnlyLower` give `max(speed, 0.25)` below 1; speed 0 gives 0) into `ReplaySoundMath.SpeedPitch`, and the order of `SimSpeedRule` into `SoundSpeedRule`, so check both on an update. Without the patch the replay plays no engine sound, because the game holds the sim at speed 0 and every sound then gets the pitch 0.

### Game sound (`Features/Sound`, `Features/Replay/ReplaySound.cs`)

The sound features use no Harmony patch except the pitch prefix above, but they call the FMOD wrapper of the game (`Brutal.Fmod.dll`, namespace `Brutal.FmodApi`) directly. A missing member fails the build or throws, and the take then records no sound with a warning row and a log line.

The WAV writer owns the file and updates its header when it closes it.
If the stop wait times out, the recorder retains the writer and refuses a new sound recording and local quit until it ends.

- The recording of a take: `GameAudio.System` (`FmodSystem`), `FmodSystem.TryGetSoftwareFormat`, `TryGetMasterChannelGroup`, `TryCreateDsp(in DspDescription, out Dsp)`, `ChannelGroup.TryAddDsp` and `TryRemoveDsp` with `ChannelControlDspIndex.ChannelControlDspHead`, `Dsp.TrySetActive` and `TryRelease`. The DSP description is the struct `DspDescription` (216 bytes, the FMOD 2 layout with `PluginSdkVersion` 110) with only `Name`, `Version`, `NumInputBuffers`, `NumOutputBuffers` and `Read` set. `DspReadCallbackPtr` takes only a delegate, so the mod writes the pointer of an `UnmanagedCallersOnly` method into its one field (`nint`); check that the struct still has exactly that one field. The read callback has the FMOD signature `(DspState*, float* in, float* out, uint length, int inChannels, int* outChannels)` and runs on the mixer thread. The game volume groups (`GameAudio.GetChannelGroup`) are code-made groups under the FMOD master group, so the DSP at the head of the master group hears all of them after their volumes.

The replay finds parts by `Part.Template.Id`, `Part.Id` and `Part.DisplayName` with `Part.PositionVehicleAsmb` of the decoded part tree, and the camera of the replay writes `Camera.PositionEcl`, `Camera.LocalRotation` and then `FlyController.CacheOffset()`, which must still only store the rotation. The take camera of a replay uses the fixed mode with no followed object, so `FixedController.OnFrame` must still leave the camera alone without `Camera.Following` and `FixedController.OnKey` must still take no key. The recorder follows the controlled vehicle through `VehicleReader.TryFollow` as a live take does (`DockingPort.Undock`, `DockingPort.Dock`, `PartFailureEvent.Apply` must still give the control to the vehicle with the parts). An old saved view turns into a camera direction with `Camera.ForwardView`.

### Replay render state restoration

- `ReplayCloudState` reads and restores private `CloudLayerRenderData` fields `_noiseScroll`, `_noiseScrollAtFrameStart`, `_noiseFrameMovementInCloudSpace`, `_twoDimensionalFlowMapPhase` and `_volumetricsFlowMapPhase`. Prefixes on `UpdateCommonFrameData` and `UpdateVolumetricsFrameData` snapshot each layer before replay movement. On close, `_lastCommonFrameUpdate` and `_lastVolumetricsFrameUpdate` become `ulong.MaxValue` so the next live frame rebuilds cached shader data. Missing snapshot hooks or fields disable replay cloud steps.
- `KittenRenderable.UpdateRenderData` contains four calls each of `Universe.GetSimulationSpeed` and `Universe.GetAchivedSpeedFraction`. The first, second and fourth pairs use a scoped replay state clock for recorded EVA kittens; the third pair retains the manual main-clip clock. The scope restores itself in a finally block and never changes the live sim speed. Verify the call order, MMU arm scrub and swimming blend on updates.
- `ExplosionFlashSystem.SubmitLights(IViewport)` skips the main replay viewport. Live flash slots remain unchanged while the simulation is held, and become visible again after closing.
- `ExplosionVolumeStore.Add` can replace an existing slot at capacity. Recording and replay compare volume identities across `ExplosionVolumeManager.Spawn` to preserve the inserted volume seed after replacement. A merge retains the existing object and seed. Seeks consider all earlier explosions and use `ExplosionVolumeTemplate.GetScaledLifeSeconds` to skip expired volumes.
- Format 3 can retain a terminal effects tail in `ReplayFlight.EndTime`; actors stop at their recorded end and are not sampled after destruction. A take that ends on a destroyed vehicle leaves its recorder alive through the effects frame. `MissionProgress.FindRelation` supplies the read-only arrival state at an SOI boundary before `ArrivedAt` is populated.

## Localization maintenance

The interface text and the language support decision are documented in [localization.md](localization.md).
Add an English fallback and entries in both embedded JSON tables for each new visible message.
Use `UiText.Format` for interpolated messages and `UiText.Concat` or `UiText.Join` when messages are combined.
Call `UiText.Render` only at a presentation boundary.
Keep control IDs, user text and protocol data canonical.
Run the localization coverage tool and the locale tests after a UI change.
On a game update, check `GameContentTags.Build`, `LanguageFileReference.DoLoad`, `Languages.AddOrAppend`, the `LStrings` provider setup, the available stock locales and any exposed active-language setting.
The language table adds no Harmony target or reflection key to the runtime mod.
